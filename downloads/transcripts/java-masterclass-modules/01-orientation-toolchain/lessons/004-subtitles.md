# Lesson 004 — Subtitles và technical listening

## Nội dung chính

Bài giới thiệu subtitles tiếng Anh được biên tập thủ công và subtitles ngôn ngữ khác có thể do machine translation tạo ra. Người học được khuyến khích dùng subtitle khi accent hoặc tốc độ nói gây khó hiểu.

## Kỹ năng kỹ thuật liên quan

Subtitles không chỉ để dịch. Với lập trình, người học cần nhận diện chính xác:

- tên class/method;
- version number;
- keyword;
- exception;
- package;
- câu điều kiện và phủ định.

Nghe nhầm một keyword có thể làm sai cả mental model. Ví dụ “not part of the JDK” khác hoàn toàn “part of the JDK”.

## Workflow đọc subtitle

1. Nghe câu đầu tiên mà không nhìn.
2. Đọc subtitle để xác nhận thuật ngữ.
3. Dừng và tra API/keyword chưa biết.
4. Ghi lại spelling chính xác.
5. Tự dùng thuật ngữ đó trong một câu/code comment.

Giữ technical terms bằng English; phần giải thích có thể bằng tiếng Việt.

## Những gì không nên làm

- Tin machine subtitle tuyệt đối ở câu code dài.
- Dịch tên API thành tiếng Việt rồi tìm sai tài liệu.
- Copy một câu subtitle mà không kiểm tra transcript/source code.
- Bỏ qua timestamp khi phát hiện lỗi thuật ngữ.

## Interview prompts

1. Vì sao tên API cần giữ nguyên English?
2. Khi nghe nhầm một keyword, bạn xác minh thế nào?
3. Documentation và subtitle khác vai trò ra sao?

## Practice

Chọn 10 technical terms trong module Java đầu tiên. Ghi spelling, pronunciation gần đúng, package/API liên quan và một ví dụ dùng. Tạo glossary riêng cho course.

## Kết luận

Subtitle là công cụ giảm lỗi nhận thức khi học; source code và documentation vẫn là nơi xác nhận cuối cùng.
